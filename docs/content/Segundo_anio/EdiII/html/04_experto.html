Scripting Avanzado en Bash

El poder de la automatización con scripts

El shell scripting es lo que convierte a Linux en una plataforma tan potente para la automatización. A través de los scripts de Bash puedes combinar múltiples comandos, tomar decisiones lógicas y repetir tareas, lo que te permite automatizar procesos complejos que normalmente requerirían intervención manual constante.

En el nivel experto, un usuario de Linux debe ser capaz de crear scripts sofisticados que puedan manejar casos de error, procesar datos de múltiples fuentes y ejecutar tareas complejas de manera autónoma.

Estructuras de control avanzadas
🔄

Las estructuras de control en Bash permiten crear scripts con lógica compleja, toma de decisiones y manejo de diferentes escenarios.

¿Por qué deberías conocerlas?

Las estructuras avanzadas de control te permiten crear scripts robustos capaces de manejar situaciones imprevistas, procesar datos de forma inteligente y tomar decisiones basadas en múltiples condiciones. Sin estas herramientas, tus scripts serían lineales y frágiles, incapaces de adaptarse a diferentes situaciones.

#!/bin/bash # Ejemplo de estructura case read -p "Ingrese un comando (backup/status/update): " comando case "$comando" in backup) echo "Iniciando backup..." # Código para el backup ;; status) echo "Verificando estado del sistema..." if systemctl is-active --quiet apache2; then echo "El servidor web está activo" else echo "El servidor web está inactivo" fi ;; update) echo "Actualizando el sistema..." # Código para actualización ;; *) echo "Comando no reconocido: $comando" exit 1 ;; esac # Ejemplo de bucle for con múltiples fuentes echo "Verificando espacio en discos:" for disco in /dev/sd{a,b,c}; do if [ -e "$disco" ]; then echo -n "$disco: " df -h "$disco" 2>/dev/null | grep -v Filesystem || echo "No montado" fi done # Ejemplo de bucle while con lectura de archivo echo "Procesando usuarios:" while IFS=: read -r usuario _ uid gid _ home shell; do if [ "$uid" -ge 1000 ] && [ "$uid" -lt 60000 ]; then echo "Usuario: $usuario, UID: $uid, Home: $home, Shell: $shell" fi done < /etc/passwd

Estructuras de control en Bash:

  • if/elif/else: Evaluación de condiciones
  • case: Evaluación múltiple de un valor
  • for: Iteración sobre listas o rangos
  • while: Bucle mientras una condición sea verdadera
  • until: Bucle hasta que una condición sea verdadera
  • select: Menú interactivo
  • Expansiones: {a,b,c}, {1..10}
Ejercicios para practicar:
  1. Crea un script que reciba como parámetro un directorio y muestre los 5 archivos más grandes.
  2. Escribe un script que procese línea por línea un archivo CSV y realice una acción diferente según el valor de la primera columna.
  3. Implementa un menú interactivo con select que permita ejecutar diferentes utilidades del sistema.
  4. Crea un script que recorra todos los usuarios del sistema y compruebe si su directorio home existe y tiene los permisos correctos.
Funciones y modularización
🧩

Las funciones permiten organizar y reutilizar código en scripts Bash, mejorando la legibilidad y mantenimiento.

¿Por qué deberías conocerlas?

Al igual que en cualquier lenguaje de programación, las funciones son esenciales para crear código limpio y mantenible. Te permiten dividir problemas complejos en piezas más pequeñas y reutilizables, evitando duplicación de código y facilitando el mantenimiento a largo plazo de tus scripts.

#!/bin/bash # Definición de funciones con parámetros y valor de retorno verificar_espacio() { local directorio="$1" local minimo="${2:-100}" # Valor por defecto: 100MB # Obtener espacio libre en MB local espacio_libre=$(df -m "$directorio" | awk 'NR==2 {print $4}') if [ "$espacio_libre" -lt "$minimo" ]; then echo "ADVERTENCIA: Queda poco espacio en $directorio ($espacio_libre MB)" return 1 else echo "Espacio suficiente en $directorio ($espacio_libre MB)" return 0 fi } # Función para log con timestamp log() { local nivel="$1" local mensaje="$2" local timestamp=$(date '+%Y-%m-%d %H:%M:%S') echo "[$timestamp] [$nivel] $mensaje" >> "/var/log/miscript.log" # Si es error, también mostrar en stderr if [ "$nivel" = "ERROR" ]; then echo "[$timestamp] [$nivel] $mensaje" >&2 fi } # Función para limpieza antes de salir limpiar() { echo "Realizando limpieza..." [ -f "$TEMP_FILE" ] && rm "$TEMP_FILE" log "INFO" "Script finalizado, recursos liberados" } # Registrar función de limpieza para que se ejecute al salir trap limpiar EXIT # Uso de las funciones TEMP_FILE=$(mktemp) log "INFO" "Script iniciado con PID $$" verificar_espacio "/home" 500 if [ $? -eq 0 ]; then echo "Procediendo con la operación..." log "INFO" "Verificación de espacio exitosa" else log "ERROR" "Espacio insuficiente para continuar" exit 1 fi

Características avanzadas de funciones:

  • Variables locales con local
  • Parámetros posicionales: $1, $2, etc.
  • Parámetros con valores por defecto
  • Retorno de valores mediante return
  • Captura de la salida con $(funcion)
  • Uso de trap para manejar señales y limpieza
Ejercicios para practicar:
  1. Crea un script con funciones para realizar operaciones comunes de administración (comprobar espacio, verificar procesos, etc.).
  2. Implementa un sistema de log que registre información en archivos diferentes según el nivel (INFO, WARNING, ERROR).
  3. Escribe una función de validación que verifique si un parámetro cumple ciertos requisitos (formato, rango, etc.).
  4. Desarrolla una biblioteca de funciones reutilizables y un script principal que las importe con source.
Depuración y manejo de errores
🐛

Los scripts profesionales deben incluir técnicas robustas de depuración y manejo de errores para garantizar su confiabilidad.

¿Por qué deberías conocerlo?

Los scripts que se ejecutan en entornos de producción deben ser confiables y capaces de manejar situaciones imprevistas. Las técnicas de depuración te ayudan a identificar problemas, mientras que el manejo adecuado de errores evita que los scripts fallen silenciosamente o causen daños cuando algo sale mal.

#!/bin/bash # Habilitar modo de depuración # set -x # Descomentar para mostrar cada comando ejecutado # Fallar ante cualquier error set -e # Fallar si se usa una variable no definida set -u # Fallar si cualquier comando en una tubería falla set -o pipefail # Función para manejar errores manejar_error() { local linea=$1 local comando=$2 local codigo=$3 echo "ERROR en línea $linea ejecutando: $comando (código: $codigo)" >&2 # Enviar correo de notificación en caso de error crítico if [ "$codigo" -gt 100 ]; then echo "Error crítico en script $0" | mail -s "ERROR CRÍTICO" admin@ejemplo.com fi # Limpieza antes de salir [ -f "$TEMP_FILE" ] && rm "$TEMP_FILE" exit $codigo } # Registrar el manejador de errores trap 'manejar_error $LINENO "$BASH_COMMAND" $?' ERR # Archivo temporal seguro TEMP_FILE=$(mktemp) # Verificar dependencias for cmd in ffmpeg convert identify; do if ! command -v "$cmd" &> /dev/null; then echo "ERROR: Comando '$cmd' no encontrado. Por favor instálelo." >&2 exit 1 fi done # Validación de parámetros if [ $# -lt 2 ]; then echo "Uso: $0 ARCHIVO_ENTRADA DIRECTORIO_SALIDA [OPCIONES]" >&2 exit 1 fi ARCHIVO_ENTRADA="$1" DIRECTORIO_SALIDA="$2" if [ ! -f "$ARCHIVO_ENTRADA" ]; then echo "ERROR: El archivo '$ARCHIVO_ENTRADA' no existe" >&2 exit 2 fi if [ ! -d "$DIRECTORIO_SALIDA" ] || [ ! -w "$DIRECTORIO_SALIDA" ]; then echo "ERROR: El directorio '$DIRECTORIO_SALIDA' no existe o no se puede escribir" >&2 exit 3 fi # Procesamiento principal protegido con bloques try-catch simulados { echo "Procesando archivo: $ARCHIVO_ENTRADA" # Comandos de procesamiento... # Simular un comando que podría fallar if ! cp "$ARCHIVO_ENTRADA" "$DIRECTORIO_SALIDA/"; then exit 100 # Código de error personalizado fi echo "Procesamiento completado con éxito" } || { # Este bloque se ejecutará si cualquier comando en el bloque anterior falla echo "ERROR: Fallo en el procesamiento principal" >&2 exit 4 }

Técnicas de depuración y manejo de errores:

  • set -x: Modo de depuración (muestra comandos)
  • set -e: Termina el script si algún comando falla
  • set -u: Falla si se usa una variable no definida
  • set -o pipefail: Detecta fallos en tuberías (pipes)
  • trap: Captura señales y errores
  • Validación de entradas y parámetros
  • Códigos de retorno personalizados
  • Redirección de errores a archivos de log
Ejercicios para practicar:
  1. Actualiza un script existente para que utilice set -euo pipefail y maneja los posibles errores.
  2. Crea un script que valide exhaustivamente sus parámetros antes de proceder con la ejecución.
  3. Implementa un sistema de "try-catch" simulado usando subshells y comprobación de códigos de retorno.
  4. Desarrolla un script con un sistema completo de logs que registre información detallada sobre errores, incluyendo línea y comando.
Evaluación de comandos y expansiones
🔍

Bash ofrece poderosas técnicas para evaluar comandos, manipular resultados y realizar expansiones complejas.

¿Por qué deberías conocerlas?

Estas técnicas avanzadas te permiten manipular datos de manera más eficiente y escribir scripts más compactos y potentes. Dominándolas, podrás realizar tareas complejas con menos código y mayor elegancia, aprovechando al máximo las capacidades del shell.

# Sustitución de comandos $ usuarios=$(cut -d: -f1 /etc/passwd | sort) $ echo "Primer usuario: $(echo "$usuarios" | head -1)" Primer usuario: root # Sustitución aritmética $ echo "3 + 4 * 2 = $((3 + 4 * 2))" 3 + 4 * 2 = 11 # Expansión de llaves para nombres de archivo $ mkdir -p proyecto/{src,doc,test}/{main,util,lib} $ ls -la proyecto/ total 12 drwxr-xr-x 5 usuario grupo 4096 Oct 15 14:20 . drwxr-xr-x 3 usuario grupo 4096 Oct 15 14:20 .. drwxr-xr-x 5 usuario grupo 4096 Oct 15 14:20 doc drwxr-xr-x 5 usuario grupo 4096 Oct 15 14:20 src drwxr-xr-x 5 usuario grupo 4096 Oct 15 14:20 test # Expansión de variables con valores por defecto $ echo "Valor actual: ${VAR:-valor_predeterminado}" Valor actual: valor_predeterminado $ VAR="existente" $ echo "Valor actual: ${VAR:-valor_predeterminado}" Valor actual: existente
#!/bin/bash # Ejemplo de script usando expansiones avanzadas # Manipulación avanzada de strings archivo="documento.principal.txt.backup" echo "Nombre base: ${archivo%.*}" # documento.principal.txt echo "Extensión: ${archivo##*.}" # backup echo "Sin prefijo: ${archivo#documento.}" # principal.txt.backup echo "Reemplazo: ${archivo/principal/secundario}" # documento.secundario.txt.backup # Expansión de variables con validaciones directorio=${1:-$(pwd)} # Usa el primer parámetro o el directorio actual usuario=${SUDO_USER:-$USER} # Usa SUDO_USER si existe, o USER si no memoria=${RAM_MINIMA:=512} # Asigna 512 si RAM_MINIMA no está definida # Verificación de variable y salida con error si no existe : ${CONFIG_FILE:?"Variable CONFIG_FILE no definida"} # Uso de indirección (variables que contienen nombres de otras variables) tipo="ERROR" ERROR_MSG="Este es un mensaje de error" INFO_MSG="Este es un mensaje informativo" echo "Mensaje: ${!tipo"_MSG"}" # Muestra ERROR_MSG # Expansión de rangos for i in {01..10}; do echo "Procesando archivo_$i.txt" done # Expansión de nombres de archivo existentes for archivo in /etc/cron.{d,daily,hourly,monthly,weekly}/*; do [[ -f $archivo ]] && echo "Archivo cron: $archivo" done # Asignación múltiple basada en salida de comando read dia mes año <<< $(date +'%d %m %Y') echo "Hoy es: $dia/$mes/$año" # Usar xargs para procesar varios archivos de manera eficiente find /var/log -name "*.log" -mtime +30 | xargs -r rm -f

Técnicas avanzadas de expansión:

  • Sustitución de comandos: $(comando)
  • Evaluación aritmética: $((expresion))
  • Expansión de llaves: {a,b,c}, {1..10}
  • Manipulación de strings: ${var#patron}, ${var%patron}
  • Valores por defecto: ${var:-valor}
  • Asignación si no existe: ${var:=valor}
  • Error si no existe: ${var:?mensaje}
  • Indirección: ${!varname}
  • Expansión de substrings: ${var:posicion:longitud}
Ejercicios para practicar:
  1. Crea un script que utilice expansión de llaves para generar una estructura de directorios compleja.
  2. Escribe un script que procese nombres de archivo realizando diferentes manipulaciones de strings (obtener extensión, reemplazar partes, etc.).
  3. Implementa un sistema de configuración que use valores por defecto para variables no definidas.
  4. Desarrolla un script que utilice el mayor número posible de técnicas de expansión diferentes.

Automatización y Programación de Tareas

Administrando tareas programadas

Uno de los aspectos más potentes de los sistemas Linux es la capacidad de programar la ejecución automática de tareas. Esto permite a los administradores configurar el sistema para que realice mantenimiento rutinario, copias de seguridad, procesamiento por lotes y otras tareas sin intervención manual.

Los usuarios expertos de Linux dominan no solo cómo programar tareas, sino también cómo monitorearlas, solucionar problemas y gestionar adecuadamente sus salidas y notificaciones.

cron y crontab avanzado
🕒

Cron es el programador de tareas estándar en sistemas Linux, permitiendo la ejecución de comandos en momentos específicos de forma recurrente.

¿Por qué deberías dominarlo?

La capacidad de programar tareas de forma precisa y confiable es crucial para la administración de sistemas. Con cron puedes automatizar completamente el mantenimiento rutinario, generación de informes, copias de seguridad y muchas otras tareas, liberando tiempo y asegurando que nada se olvide o retrase.

# Editar el crontab del usuario actual $ crontab -e # Formato de crontab: minuto hora día-mes mes día-semana comando # Ejecutar a las 3:30 AM todos los días 30 3 * * * /ruta/al/script_backup.sh # Ejecutar cada 15 minutos en horario laboral (Lun-Vie, 9-17) */15 9-17 * * 1-5 /ruta/al/script_monitoreo.sh # Ejecutar el primer día de cada mes a medianoche 0 0 1 * * /ruta/al/script_mensual.sh # Ejecutar cada domingo a las 2 AM 0 2 * * 0 /ruta/al/script_semanal.sh # Ver las tareas programadas $ crontab -l [muestra las entradas del crontab] # Ver las tareas programadas de otro usuario (como root) # crontab -u otroUsuario -l

Características avanzadas de cron:

  • Expresiones especiales: @yearly, @monthly, @weekly, @daily, @hourly, @reboot
  • Variables de entorno en crontab
  • Redirección de salida y errores
  • Directorios especiales: /etc/cron.d/, /etc/cron.daily/, etc.
  • Restricción de usuarios con /etc/cron.allow y /etc/cron.deny
  • Uso de anacron para sistemas que no están siempre encendidos
# Ejemplo de crontab avanzado # Configurar variables de entorno SHELL=/bin/bash PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin MAILTO=admin@ejemplo.com # Redirección de salida y errores a archivos de log 0 2 * * * /scripts/backup_db.sh >> /var/log/backup_db.log 2>&1 # Usar hora específica con entorno completo 0 5 * * * . $HOME/.profile; /scripts/informe_diario.sh # Ejecutar con prioridad baja usando nice 30 3 * * * nice -n 19 /scripts/tarea_pesada.sh # Configurar lock para evitar ejecuciones simultáneas 45 * * * * flock -n /tmp/script.lock /scripts/cada_hora.sh # Encadenar comandos con verificación de condiciones 0 1 * * * [ $(date +\%d) -eq 1 ] && /scripts/primer_dia_mes.sh # Usar variantes de horario 0 0 * * * [ $(date +\%u) -eq 6 ] && /scripts/fin_de_semana.sh # Ejecutar al iniciar el sistema @reboot /scripts/inicio_sistema.sh
Ejercicios para practicar:
  1. Configura una tarea cron que realice una copia de seguridad de tus documentos cada viernes a las 18:00.
  2. Crea un crontab que ejecute diferentes scripts según el día del mes (1-10, 11-20, 21-31).
  3. Implementa un sistema de log rotativo para un script ejecutado por cron (usa logrotate).
  4. Configura un script para ser ejecutado por cron que verifique primero si otro proceso similar está en ejecución.
