Resumen: Ingeniería de Requerimientos

1. ¿Qué son los Requerimientos del Sistema?

Son características o prestaciones que el sistema debe cumplir para satisfacer las necesidades del negocio y los usuarios.

  • Funcionales: Servicios que el sistema debe proporcionar.
  • No funcionales: Restricciones operativas (ej. seguridad, escalabilidad).

2. Desafíos Comunes

  • Imprecisión: Uso de lenguaje natural puede generar malentendidos.
  • Acuerdo: Dificultad para alinear a todos los involucrados.
  • Arrastre: Cambios en el personal o contexto afectan los requerimientos.

3. Técnicas para Recolectar Requerimientos

  • Entrevistas: Identificar personas clave, preparar preguntas y documentar.
  • Revisión de Documentos: Analizar sistemas existentes.
  • Observación: Ver cómo se usan los sistemas actuales.
  • Encuestas: Útiles para recopilar datos de muchas personas.
  • Técnicas Ágiles: Historias de usuario, escenarios y storyboards.

4. Representación de Requerimientos

  • Lenguaje Natural: Fácil de usar, pero propenso a errores.
  • Diagramas: Visualización clara (ej. diagramas de flujo, casos de uso).
  • Modelos: Representaciones formales con semántica para análisis automático.

5. Validación y Verificación

Asegurar que los requerimientos reflejen lo que el cliente realmente necesita. Detectar errores temprano para evitar costos elevados en etapas avanzadas.

6. Herramientas Útiles

Ejemplos: LibreOffice, Leanote, Reqflow, Doorstop.

Conclusión

La ingeniería de requerimientos es clave para garantizar que el sistema cumpla con las expectativas del negocio y los usuarios, utilizando técnicas y herramientas adecuadas para recolectar, representar y validar la información.
